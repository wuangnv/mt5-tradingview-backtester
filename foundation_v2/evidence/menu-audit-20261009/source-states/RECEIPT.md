# Dashboard independent source states — 09/10/2026

Implemented within `DashboardSessions.jsx`, `DashboardSessionCard.jsx`, `PropAnalytics.jsx`, and the dataset read boundary in `dashboardModel.js`; API/backend/trading behavior unchanged. Two localized dataset-source messages were added to `testing-copy.json`.

- Recent Sessions marks a successful read explicitly, including a successful empty list. Same-scope refresh/503 retains verified cards or verified empty results, shows updating/stale and Retry, and blocks edit/delete/duplicate plus an already-open dialog's submit until the catalog is reconciled. Initial failures have one owning alert. A 401/403 clears cached cards, detail state, and open session dialogs; independent dataset metadata is cleared by its own permission response.
- Prop reports retain a verified report, chooser, or empty result during same-scope refresh/retry and show updating/stale. A 401/403 clears cached reports. Response validation catches missing render-required phase/profile/outcome objects and nonstring identifiers before rendering; malformed responses remain a local source error rather than crashing the Dashboard route.
- Rendered Prop fields also validate phase index, terms version, outcome status, optional timestamp and evaluation quality scalar types. Report time uses the existing date formatter: `dd/mm/yyyy HH:mm:ss`, preserving UTC.
- A failed session detail has a local Retry action on its expanded card; retry evicts only the failed entry, preserving correctly cached ready details. The aggregate Strategy/profit warning can retry failed entries together. Both entry points and the retry handler are blocked while the catalog is refreshing, stale or unverified.
- Dataset metadata has its own successful-read marker, refresh/stale/error states and local retry. A transient refresh failure retains verified date/remaining-time metadata with an explicit source warning; a 401/403 clears that metadata. Invalid entries such as `items:[null]` fail at the read boundary. A metadata failure never means sessions are empty and never hides their catalog cards.
- The main shell uses normal navigation and `DashboardSessions key={workspace}` (`main.jsx:35`). No new workspace router or speculative prop-transition architecture was introduced.

Validation: `node tests/dashboardSourceStates.browser.mjs` passed **26 cases** in dark/light themes, with external-origin and non-GET API guards, no JS errors, and no API writes. Fixtures cover stale retention, retry retention, open-dialog/card mutation blocking, permission revocation, initial errors, malformed objects/scalar IDs/rendered fields, successful empty refresh failures, and 360px layout. Aggregate detail retry stays unavailable during catalog refresh/stale; the failed cache is retained, then recovers after catalog verification. Failed-detail GET count changes from 1 to 2 after retry while ready sibling count stays 1. Local dataset retry makes exactly one additional dataset GET, preserving analytics counts; dataset initial error/403/malformed entry leaves both session cards present. Prop report date is asserted as `09/10/2026 12:34:56`. `npm run build` and `git diff --check` pass after the final implementation. ## Audit findings closed in this slice

The two confirmed omissions from the first audit—no failed-detail retry and silent metadata erasure on refresh failure—are now implemented and covered above. Source boundaries also reject the malformed Prop/dataset payloads found by independent review.

This slice does not expand individual report-renderer contracts, form server-conflict flows, or workspace-transition behavior in unkeyed consumers. Replay-context reads within each session detail remain best-effort optional metadata; this does not claim independent context-source retry semantics or whole-project synchronization.
